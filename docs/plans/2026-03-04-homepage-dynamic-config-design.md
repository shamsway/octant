# Homepage Dynamic Config Generation - Design

**Date:** 2026-03-04
**Branch:** `feature/app-migration`
**Status:** Draft

## Goal

Replace Homepage's static `services.yaml` with a config generated from standardized Nomad service tags, so the dashboard stays in sync with deployed services automatically.

## Context

Homepage (`terraform/homepage/`) serves as the lab's dashboard at `homepage.lab.shamsway.net`. Its `config/services.yaml` is a static file listing 22 services across 6 categories. This config drifts every time a service is added, removed, or renamed — the recent wave of deployments (Docmost, Fusion, Gitea, Linkding, Linkwarden, FalkorDB, Graphiti, Rocket.Chat, OpenClaw) added 9 services, none of which appear on the dashboard.

Homepage supports Docker/Kubernetes auto-discovery via container labels, but has **no native Nomad or Consul provider**. The solution is to embed Homepage-relevant metadata in Nomad service tags (which flow into Consul), then generate `services.yaml` from the Nomad API with a simple Python script.

### Current State

- 38 Nomad jobs running, ~30 with Consul service registrations
- Tags are exclusively Traefik routing tags — no metadata beyond routing
- No `meta {}` blocks used at job, group, or service level
- `services.yaml` has 22 entries, many services missing
- Homepage config is volume-mounted from `/mnt/services/homepage/config/`

## Architecture

```
Nomad Job Specs (.nomad.hcl)
  └── service.tags[] includes homepage.* tags
          │
          ▼
    Nomad API (/v1/jobs → /v1/job/<id>)
          │
          ▼
    Python script (generate-homepage-config.py)
      - Queries all running jobs
      - Extracts homepage.* tags from each service
      - Groups by category, sorts within groups
      - Renders services.yaml + settings.yaml
          │
          ▼
    /mnt/services/homepage/config/services.yaml
    /mnt/services/homepage/config/settings.yaml
```

## Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Metadata carrier | Service tags (not `meta {}`) | Tags flow to Consul automatically; `meta` blocks are job-level only and don't attach to service registrations. Consul `ServiceMeta` requires `meta {}` inside the `service` block which Nomad supports but adds HCL complexity. Tags are simpler — one flat list already in use. |
| Tag prefix | `homepage.` | Mirrors the Docker label convention Homepage uses (`homepage.group`, `homepage.name`, etc.). Familiar to anyone who's used Homepage with Docker. |
| Script language | Python | Available on all nodes, no dependencies beyond `urllib`/`json`/`yaml` (stdlib + PyYAML). Simple enough to not need a framework. |
| Execution model | Nomad batch job on cron, or manual script | Avoids a long-running sidecar. Run on change or periodically. Can also be run ad-hoc during development. |
| Config scope | `services.yaml` + `settings.yaml` | These are the two files that change when services are added. `bookmarks.yaml` and `widgets.yaml` are editorial and stay manual. |
| Services without tags | Excluded from generated config | Infrastructure services (postgres, redis, mariadb) and batch jobs that don't need dashboard entries simply omit homepage tags. The script ignores services without `homepage.group`. |

## What Gets Changed

| Component | Current State | Target State | Notes |
|-----------|--------------|--------------|-------|
| `terraform/*/nomad.hcl` (all services) | Traefik-only tags | Add `homepage.*` tags | ~25 files |
| `terraform/homepage/config/services.yaml` | Static, hand-maintained | Generated by script | Committed version becomes a reference/fallback |
| `terraform/homepage/config/settings.yaml` | Static, hand-maintained | Generated layout section from discovered groups | Theme/color/favicon stay static |
| `scripts/generate-homepage-config.py` | Does not exist | New script | Queries Nomad API, writes YAML |

## Section 1: Tag Standard

### Tag Format

Tags use `key=value` format within the existing Nomad service `tags` list. All homepage tags use the `homepage.` prefix:

| Tag | Required | Description | Example |
|-----|----------|-------------|---------|
| `homepage.group` | Yes | Dashboard category/section | `homepage.group=Monitoring` |
| `homepage.name` | Yes | Display name on dashboard | `homepage.name=Grafana` |
| `homepage.icon` | Yes | Icon identifier (dashboard-icons, si-*, sh-*) | `homepage.icon=grafana` |
| `homepage.description` | Yes | Short description | `homepage.description=Dashboards` |
| `homepage.href` | No | URL override (default: derived from Traefik tags) | `homepage.href=http://traefik.lab.shamsway.net:9002` |
| `homepage.weight` | No | Sort order within group (lower = first, default 50) | `homepage.weight=10` |
| `homepage.enabled` | No | Set to `false` to exclude (default: `true` if group tag present) | `homepage.enabled=false` |

### URL Derivation

If `homepage.href` is not specified, the script derives it from the Traefik router `Host()` rule:
1. Find `traefik.http.routers.*.rule=Host(...)` tag
2. Extract the hostname
3. Use `https://<hostname>` as the href

If no Traefik Host rule is found and no `homepage.href` is set, the service entry is rendered without an `href` (icon + description only, like current PostgreSQL/MariaDB entries).

### Group Names

Standardize on these group names (matching existing `settings.yaml` layout):

| Group | Services |
|-------|----------|
| Infrastructure | Traefik, Nomad (bookmark), Nginx, Consul (bookmark) |
| Monitoring | Grafana, Prometheus, Gatus, Uptime Kuma, Alertmanager |
| Observability | Loki, Tempo, Alloy |
| Databases | PostgreSQL, MariaDB, pgAdmin, Qdrant, Redis, Neo4j, FalkorDB, MongoDB |
| Apps | SearXNG, Excalidraw, n8n, IT-Tools, Linkding, Linkwarden, Fusion, Docmost, Gitea, Rocket.Chat, PlantuML |
| AI & LLM | LiteLLM, Phoenix, Open WebUI, OpenClaw, Graphiti |

### Example: Grafana Job Tags

Current:
```hcl
tags = [
  "traefik.enable=true",
  "traefik.consulcatalog.connect=false",
  "traefik.http.routers.grafana.rule=Host(`grafana.${domain}`)",
  "traefik.http.routers.grafana.entrypoints=web,websecure",
  "traefik.http.routers.grafana.tls.certresolver=${certresolver}",
  "traefik.http.routers.grafana.middlewares=redirect-web-to-websecure@internal",
]
```

Target (appended):
```hcl

  "traefik.enable=true",
  "traefik.consulcatalog.connect=false",
  "traefik.http.routers.grafana.rule=Host(`grafana.${domain}`)",
```

## Section 2: Python Generator Script

### Location

`scripts/generate-homepage-config.py`

### Behavior

1. **Query Nomad API** at `http://localhost:4646`
   - `GET /v1/jobs` — list all jobs
   - For each running job: `GET /v1/job/<id>` — get full spec with services/tags
2. **Extract homepage tags** from each service's tag list
   - Parse `homepage.key=value` pairs
   - Skip services without `homepage.group`
   - Skip services with `homepage.enabled=false`
3. **Derive missing hrefs** from Traefik `Host()` rules
4. **Group and sort** services by `homepage.group`, then by `homepage.weight` (default 50), then alphabetically by `homepage.name`
5. **Generate `services.yaml`** in Homepage's expected format:
   ```yaml
   ---
   - Infrastructure:
       - Traefik:
           icon: traefik
           href: http://traefik.lab.shamsway.net:9002
           description: Reverse Proxy
       - Nginx:
           icon: nginx
           href: https://nginx.lab.shamsway.net
           description: Static Web Server
   ```
6. **Generate layout section for `settings.yaml`** — compute column count per group (min 2, max 5, based on service count), merge with static settings (theme, favicon, etc.)
7. **Write files** to the output directory (default: `/mnt/services/homepage/config/`)

### CLI Interface

```
usage: generate-homepage-config.py [-h] [--nomad-addr URL] [--output-dir DIR] [--dry-run]

Options:
  --nomad-addr URL    Nomad API address (default: http://localhost:4646)
  --output-dir DIR    Output directory (default: /mnt/services/homepage/config)
  --dry-run           Print generated YAML to stdout, don't write files
```

### Dependencies

- Python 3 stdlib: `urllib.request`, `json`, `argparse`, `collections`
- `PyYAML` — for YAML output (available via `pip install pyyaml` or system package)

### Error Handling

- If Nomad API is unreachable, exit with error (don't overwrite existing config)
- If a job inspection fails, log a warning and skip that job
- If zero services have homepage tags, exit with error (likely misconfiguration)

## Section 4: Execution Options

### Option A: Manual Script (MVP)

Run the script manually after deploying or removing services:
```bash
python3 scripts/generate-homepage-config.py --nomad-addr http://localhost:4646
```

### Option B: Nomad Periodic Batch Job

A Nomad batch job that runs every 15 minutes:
```hcl
job "homepage-config-gen" {
  type = "batch"
  periodic {
    cron             = "*/15 * * * *"
    prohibit_overlap = true
  }
  # ...runs the python script against Nomad API
}
```

### Option C: Terraform Local-Exec

Add a `null_resource` to `terraform/homepage/main.tf` that runs the script after the homepage job deploys. Couples config generation to homepage deploys only.

### Recommendation

**Start with Option A** (manual). It's the simplest path and config doesn't change frequently enough to justify automation yet. Move to Option B if the lab grows to 50+ services or if services churn frequently.

## Non-Goals

- **Homepage widgets/integrations**: This PRD covers only service listing. Widget configuration (API-backed status indicators) is a separate concern and stays manual.
- **Consul auto-discovery**: Homepage may add native Consul support in the future (feature request #6184). If/when that lands, it would replace this script entirely. The tag standard is designed to be compatible with a future migration.
- **Bookmarks and widgets config**: `bookmarks.yaml` and `widgets.yaml` remain hand-edited. They contain editorial content (links to GitHub, Nomad UI) not derived from service metadata.
- **Homepage Docker labels**: We're not using Docker/Podman labels since Nomad doesn't pass arbitrary labels to Podman containers. Consul service tags are the right carrier.

## Validation

After implementation:

1. **Tag verification**: For each updated service, run `terraform plan` and confirm new tags appear in the diff
2. **Script dry-run**: `python3 scripts/generate-homepage-config.py --dry-run` should produce valid YAML matching the current `services.yaml` layout (with additional services)
3. **Apply and check**: After writing config, reload `homepage.lab.shamsway.net` and verify all services appear in correct groups with working links
4. **Incremental test**: Deploy a new service with homepage tags, re-run the script, confirm it appears on the dashboard without manual YAML editing
